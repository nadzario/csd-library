# CSD Library

Открытая библиотека учебных материалов: статический каталог, загрузка файлов в несколько GitHub-репозиториев и Telegram-бот. Веб-админка и публичная форма отправки удалены; сайт на GitHub Pages не обращается к API.

## Как это устроено

```text
Яндекс Диск ── import-yandex ─┐
                              ├─ API ── GitHub Releases (файлы до 2 ГБ)
Telegram-бот ───────┘        └─ catalog.json в отдельном репозитории
                                                   │
                                                   ▼
                                      статический React-сайт (GitHub Pages)
```

- `apps/web` — статический адаптивный каталог со ссылкой на Telegram-бота.
- `apps/api` — Fastify API, публикация в GitHub и Telegram-бот.
- `packages/shared` — общая схема каталога и типы.
- `scripts/import-yandex.ts` — возобновляемая миграция публичного Яндекс Диска.
- `scripts/setup-github.ts` — создание репозиториев из конфигурации.

Бинарные файлы публикуются как Release Assets, распределённые по 16 хеш-бакетам каждого раздела. Это сохраняет git-историю лёгкой, не создаёт release на каждый файл и снимает лимит GitHub в 100 МБ на обычный объект репозитория. Метаданные лежат в одном `catalog.json`; сайт читает его во время открытия, поэтому для нового файла не требуется пересобирать фронтенд.

Веб-каталог повторяет исходную иерархию папок Яндекс Диска, показывает хлебные крошки, количество файлов и формат каждой позиции. Встроенный просмотрщик поддерживает изображения, PDF, текст и исходный код; документы DOC/DOCX, XLS/XLSX, PPT/PPTX и OpenDocument открываются через публичный Office Viewer. Для остальных форматов всегда доступна кнопка скачивания.

## Локальный запуск

Нужен Node.js 22.12+, 24.x или 26+ (рекомендуется актуальная версия 22 или 24).

```bash
npm install
cp .env.example .env
node --input-type=module -e "import fs from 'node:fs'; import {randomBytes} from 'node:crypto'; let s=fs.readFileSync('.env','utf8').replace(/^ADMIN_PASSWORD=.*$/m,'ADMIN_PASSWORD='+randomBytes(32).toString('base64url')).replace(/^JWT_SECRET=.*$/m,'JWT_SECRET='+randomBytes(48).toString('base64url')).replace(/^GITHUB_TOKEN=github_pat_replace_me$/m,'GITHUB_TOKEN=').replace(/^GITHUB_OWNER=.*$/m,'GITHUB_OWNER='); fs.writeFileSync('.env',s); fs.chmodSync('.env',0o600);"
npm run dev
```

Откройте:

- сайт — <http://localhost:5173>;
- проверка API — <http://localhost:3000/api/health>.

Без GitHub-токена каталог откроется с демонстрационными данными, но публикация будет отключена.

## Настройка GitHub

1. Выполните `gh auth login` (или `gh auth refresh -h github.com`, если сессия истекла). Локальные скрипты безопасно используют токен GitHub CLI, не выводя его в терминал. Альтернатива — fine-grained personal access token в `GITHUB_TOKEN`; ему нужны `Contents: Read and write` и `Administration: Read and write` только на время автоматического создания репозиториев. После создания достаточно прав на Contents и Releases.
2. Заполните в `.env` `GITHUB_TOKEN`, `GITHUB_OWNER`, `GITHUB_CATALOG_REPO` и `GITHUB_REPO_MAP`.
3. Создайте репозитории:

```bash
npm run github:setup
```

Рекомендуемое распределение по пяти примерно сбалансированным репозиториям уже записано в `.env.example`: `csd-early`, `csd-middle`, `csd-senior`, `csd-electives` и `csd-misc`. Можно оставить его как есть или поменять имена. Упрощённый пример:

```env
GITHUB_REPO_MAP={"1 курс":"csd-early","2 курс":"csd-early","3 курс":"csd-middle","4 курс":"csd-senior","5 курс":"csd-senior","6 курс":"csd-senior","default":"csd-misc"}
```

Все упомянутые репозитории и `csd-catalog` должны принадлежать `GITHUB_OWNER`. Скрипт делает их публичными: это важно, иначе статический сайт не сможет читать каталог и скачивать файлы без авторизации.

## Миграция Яндекс Диска

Сначала получите полный отчёт без скачивания файлов:

```bash
npm run catalog:stats
```

Он рекурсивно обходит публичную папку и пишет инвентаризацию в `data/yandex-inventory.json`. После проверки распределения репозиториев запустите перенос:

```bash
npm run import:yandex
```

Импорт работает с ограниченным параллелизмом, сверяет SHA-256 с каталогом и безопасно пропускает уже перенесённые файлы. Обновления каталога объединяются в пакеты по 100 файлов. При лимите Яндекс Диска все потоки останавливаются, а один контрольный запрос повторяется с увеличивающейся паузой от 15 минут до 2 часов. Мигратор продолжит работу автоматически, когда Яндекс снова разрешит скачивание. При другой ошибке он продолжает работу, сохраняет состояние в `data/import-state.json` и завершается с ненулевым кодом. Повторный запуск продолжит перенос за счёт проверки хешей и уже загруженных assets.

Курс определяется по первой папке, предмет — по второй. Тип материала распознаётся по словам «лекция», «экзамен», «билеты», «гайд» и т. п. После миграции названия и описания можно улучшить через манифест.

Для указанной публичной папки проверка от 22 июля 2026 года нашла **32 373 файла общим объёмом 55,57 ГиБ**. Из них 5 779 — повторения по SHA-256; импорт загрузит только 26 594 уникальных файла. Самый большой файл занимает 1,13 ГиБ, файлов больше лимита 2 ГиБ нет. Крупнейшие разделы: `3 курс` — 8 474 файла, `Нерассортированное` — 7 246, `4 курс` — 4 173.

## Telegram-бот

1. Создайте бота у `@BotFather` и добавьте токен в `TELEGRAM_BOT_TOKEN`.
2. Узнайте свой цифровой Telegram ID и внесите его в `ADMIN_TELEGRAM_IDS` (несколько ID — через запятую).
3. Перезапустите API.

Команды:

- `/start` — главное меню библиотеки;
- `/materials` — просмотр по курсам и предметам с пагинацией;
- `/search запрос` — полнотекстовый поиск по названиям, описаниям и тегам;
- `/site` — открыть расширенную веб-версию;
- `/admin` — подтверждение прав на публикацию через Telegram;
- отправка документа — публикация для разрешённых ID.

В карточке материала показываются название, описание, курс, предмет, тип, теги, размер и имя файла. Кнопка «Просмотреть / скачать» ведёт прямо на GitHub Release Asset. Каталог кэшируется ботом на пять минут и немедленно обновляется после публикации нового файла.

Подпись документа должна иметь вид:

```text
2 курс | Линейная алгебра | lecture | Конспект осеннего семестра | матрицы, экзамен
```

## Работа с материалами

Публичный сайт не содержит формы загрузки и страницы администратора.
В шапке и разделе о проекте размещена ссылка на [@csdrive_bot](https://t.me/csdrive_bot).
Публикация через бота описана выше; серверные маршруты API
сохранены для дальнейшей разработки, но Pages не использует их.

## Развёртывание

### Сайт на GitHub Pages

В настройках основного репозитория включите Pages → GitHub Actions и задайте Repository variables:

- `CATALOG_PUBLIC_URL` — `https://raw.githubusercontent.com/<owner>/<catalog-repo>/main/catalog.json`;
- `BASE_PATH` — `/` для собственного домена или `/имя-репозитория/` для project pages.

Workflow `.github/workflows/pages.yml` публикует только каталог. `/admin/` в сборке отсутствует. Для собственного домена добавьте `CNAME` в `apps/web/public`.

### API и бот

API должен работать постоянно, потому что Telegram использует long polling. Подойдёт любой Docker-хостинг (VPS, Render, Railway, Fly.io):

```bash
docker compose up -d --build
```

Передайте все переменные `.env` через менеджер секретов хостинга. Не коммитьте `.env`.

Замените пароль и JWT-ключ из `.env.example`: API отказывается запускаться
с демонстрационными значениями. Production требует явного задания обоих секретов;
development без этих переменных использует случайные значения на один запуск.
Контейнер работает от пользователя
`node` (UID/GID 1000); каталоги `./tmp` и `./data/submissions`, подключаемые
как bind mounts, должны существовать и разрешать ему запись. Подготовьте их
права на хосте до запуска Compose; права внутри образа не меняют права bind mounts.

Публичная очередь ограничена `PUBLIC_QUEUE_MAX_MB` (по умолчанию 5120 МБ),
`PUBLIC_QUEUE_MAX_FILES` (1000 файлов) и `PUBLIC_UPLOAD_CONCURRENCY` (4 загрузки).
Место резервируется до чтения файла; заполненная очередь отвечает HTTP 503.
Используйте один процесс API на локальную очередь: несколько процессов с общим
JSON-индексом требуют отдельного хранилища с блокировками.

`GITHUB_CATALOG_BRANCH` задаёт ветку каталога (по умолчанию `main`). JSON и gzip
публикуются одним Git-коммитом; конкурентное изменение ветки повторно объединяется
с актуальным каталогом. GitHub-токену нужен доступ Contents на эту ветку, а правила
защиты ветки должны разрешать публикацию выбранной учётной записи.

Systemd-unit файлы в `ops/` содержат путь `/home/nadzario/CSDGit`. Перед установкой
в другом каталоге настройте `WorkingDirectory`, `ExecStart` и пути журналов.

При запуске за обратным прокси задайте `TRUSTED_PROXIES` — список IP-адресов
или CIDR доверенных прокси через запятую (например, `127.0.0.1,::1` для
локального nginx). По умолчанию список пуст и `X-Forwarded-For` не учитывается.
Укажите только реальные адреса прокси: доверие всей сети позволяет подделывать
IP и обходить лимиты. Прокси должен корректно дополнять или перезаписывать
`X-Forwarded-For`; доступ к API в обход прокси следует ограничить на хосте.

## Длительная миграция как сервис

Для переноса большой библиотеки можно установить пользовательский systemd-unit, который продолжит работу после выхода из терминала и автоматически перезапустится после сетевой ошибки или перезагрузки:

```bash
systemctl --user link "$PWD/ops/csd-migration.service"
systemctl --user enable --now csd-migration.service
npm run migration:status
```

Подробный журнал пишется в `data/migration.log`. Остановить процесс можно командой `systemctl --user stop csd-migration.service`.

## Ограничения хранения

GitHub Releases допускают большие отдельные файлы, но у GitHub есть правила приемлемого использования и ограничения трафика. Перед полной миграцией посмотрите объём через `npm run catalog:stats`. Если библиотека занимает сотни гигабайт или имеет очень высокий трафик, бинарники лучше перенести в S3-совместимое хранилище (Cloudflare R2, Backblaze B2), оставив код, каталог и историю изменений в GitHub. Интерфейс `GitHubPublisher` изолирует этот слой, поэтому хранилище можно заменить без переделки сайта и бота.
